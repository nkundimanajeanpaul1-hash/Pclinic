PClinic — "No view URL for this file yet — is radiologyMediaSign deployed?"
=========================================================================
Build tag: 20260902_MEDIAURL     (this zip also contains the DICOM-button
                                  changes, tag 20260902_DICOMONLY)

WHAT WAS HAPPENING
------------------
Your upload DID succeed: the file is in the bucket and its record is in
Firestore (that is why "download.png" appears in the explorer). What failed
is the LAST step — turning the stored file into a link the browser may open.

radiologyMediaSign creates that link with getSignedUrl(). On Cloud Functions
the Admin SDK has no private key, so signing goes through the IAM
"signBlob" API, which needs the functions' service account to have the role
  roles/iam.serviceAccountTokenCreator
on itself. That role is not granted by default. Without it getSignedUrl()
throws, the function caught the error, and returned the item WITHOUT a url —
and the viewer, seeing no url, printed the generic guess "is
radiologyMediaSign deployed?" (it was deployed; it just could not sign).

THE FIX (two layers)
--------------------
1. Server, functions/radiology-media.cjs (new) + functions/index.js:
   - try the signed URL as before;
   - if signing fails, FALL BACK to a Firebase download-token link
     (the same kind of link the Firebase client SDK's getDownloadURL() gives:
     .../o/radiology%2F{order}%2F{id}.png?alt=media&token=…). This needs only
     storage.objects.update, which the function already has. The token is
     stored on the object once and reused, never rotated.
   - every item now carries WHY when there is still no url
     (error: object-missing | object-unavailable, reason: "…"), and the
     response says which mode it used (signing: 'signed' | 'token-fallback').
   Result: images display immediately after deploying functions, even
   before the IAM role is granted.

2. Browser, pclinic-dicom-viewer.js + pclinic-radiology-media.js:
   - the viewer shows the real reason instead of the "is it deployed?" guess
     (e.g. the signBlob permission text, "the upload did not complete", or
     "the common server is not connected"); the file stays listed and its
     Study info still renders;
   - a one-time console note explains how to restore expiring links when the
     token fallback is in use.

DEPLOY (in this order)
----------------------
  1. Extract the zip over the project root.
  2. cd functions && npm install          (no new dependencies; safe)
  3. firebase deploy --only functions:radiologyMediaSign
     (or: firebase deploy --only functions)
  4. firebase deploy --only hosting        (+ push to GitHub)
  5. Hard refresh, select the patient, "Open DICOM to add radiology result"
     → download.png now displays.

OPTIONAL — restore 10-minute expiring links (recommended for privacy)
--------------------------------------------------------------------
Grant the signing permission to the functions' runtime service account.
Project number 267628417218. Try the App Engine default account first; if
your functions run as the compute account, use the second command:

  gcloud iam service-accounts add-iam-policy-binding \
      pclinic-20d81@appspot.gserviceaccount.com \
      --member="serviceAccount:pclinic-20d81@appspot.gserviceaccount.com" \
      --role="roles/iam.serviceAccountTokenCreator" --project=pclinic-20d81

  gcloud iam service-accounts add-iam-policy-binding \
      267628417218-compute@developer.gserviceaccount.com \
      --member="serviceAccount:267628417218-compute@developer.gserviceaccount.com" \
      --role="roles/iam.serviceAccountTokenCreator" --project=pclinic-20d81

Also make sure the IAM Service Account Credentials API is enabled:
  gcloud services enable iamcredentials.googleapis.com --project=pclinic-20d81

(Console route: IAM & Admin → Service Accounts → the functions account →
Permissions → Grant access → same account as principal → role
"Service Account Token Creator".) Once granted, the function automatically
goes back to signed 10-minute links — no redeploy needed.
