================================================================

WHAT YOU GET
------------
Everything a doctor or radiologist does in the workstation is now kept on the
common server and comes back for everyone, on any device:

  • Measurements / drawings (ruler, angle, Cobb, rectangle/ellipse/freehand ROI,
    bidirectional, probe, arrow + text) — saved per image, per frame, per author.
  • Key images — ★ button in the tool bar (or key K, or the switch in
    Draw & Measure ▸ Common server). Starred thumbnails show ★; the image
    overlay shows "★ KEY IMAGE"; Study Info lists it.
  • A short note per image ("My note on this image", Draw & Measure panel).
  • "Saved ✓ 02 Sept 2026, 19:54" in the status bar (bottom right).
    While typing/drawing it says "Unsaved changes…" then "Saving…".
    Saving happens by itself 1 second after the last change — no Save button.
    If the server refuses or the connection drops it says
    "Not saved — <reason> Retrying…" in red and retries (5 s, 15 s, then every
    30 s); clicking the indicator retries at once. Closing the page, switching
    patient/study or pressing Esc flushes pending work first.

  • Colleagues' work: every doctor/radiologist sees everyone's drawings on the
    image. Your own are yellow and editable; a colleague's are green, locked
    (🔒 in the list, "by Dr Alice"), cannot be moved or deleted by you
    ("Delete all" leaves them alone). Their key-image mark and note appear
    under "From colleagues" with name, role and time.
  • Nurses see everything read-only (no ★, note box disabled).
  • Radiology's modal viewer (Open DICOM to add radiology result) saves the
    same way — one viewer, one store.
  • Same user in two tabs/devices: a drawing deleted on one disappears on the
    other (uuid-based sync) without touching what is being drawn right now.

WHERE IT IS STORED
------------------
Firestore collection  radiologyAnnotations/{mediaId}_{uid}
  id, mediaId, orderId, patientId, byUid, byId, byName, byRole,
  measurements: [{tool, uuid, frame, json}], keyImage, note, updatedAt, client
Only a description of the drawing (tool + handle coordinates + cached stats).
Never pixels, never the image — the security of study images is unchanged.
A document that becomes empty (no drawings, no ★, blank note) is deleted.

Rules (firestore.rules):
  read           every clinical role that may read the patient (patientReader)
  create/update  doctor, radio, admin — only as themselves, only for an image
                 record that exists in radiologyMedia and belongs to the same
                 order/patient, only the allowed keys, ≤300 drawings, note ≤4000
  delete         the author only (admins cannot remove a colleague's drawing)

DEPLOY (in this order)
----------------------
1. Extract this zip over the project, push to GitHub as usual.
2. Firestore rules — REQUIRED, otherwise every save says
   "Not saved — The server refused the save (permission)…":
       firebase deploy --only firestore:rules
   (no terminal? Firebase console ▸ Firestore Database ▸ Rules ▸ paste the
    whole firestore.rules file ▸ Publish)
3. If Zip A was not deployed yet:
       cd functions && npm install && cd ..
       firebase deploy --only functions
       gsutil cors set cors.json gs://pclinic-20d81.firebasestorage.app   (one time)

       firebase deploy --only hosting

LIMITS (by design)
------------------
• You can only edit/delete your own drawings; a colleague's must be changed by
  them (or deleted in the Firestore console by an admin).
• Plain JPEG/PNG shown as "plain image" (bucket CORS not set) cannot carry
  measurements — set the bucket CORS (Zip A notes).
• Drawings are per image file; if radiology removes and re-uploads a file it
  gets a new id and the old drawings no longer apply.
